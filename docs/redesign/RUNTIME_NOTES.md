That establishes local catalog support, not server entitlement or effective runtime settings. Actual effective model/effort remains unknown until a real call reports it. The installed environment has no Python Codex SDK, so the supported CLI fallback is implemented.

The CLI adapter requests read-only sandbox, disabled shell/unified execution/web/apps/multi-agent/JS, no user config, no project instructions, forced ChatGPT authentication, ephemeral sessions and zero supported HTTP/stream retries. It uses an application-visible JSON tool-request loop for both providers so retrieval/acquisition can be metered. This is a portable fresh-session approximation, not SDK continuation or native tool-trace equivalence. Configuration keys were checked against local CLI help and the [official Codex configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference). Native tool effectiveness, managed settings, response framing and effective-model reporting remain untested. Do not count such runs as guaranteed fixed-corpus comparisons until the fresh session verifies the actual controls. Application dispatch itself is tested to reject external acquisition in fixed mode.

A fresh session may load the already configured environment through the user's supported mechanism, without changing accounts or exposing secrets. No claim is made about an opaque subscription balance or dollar cost.
