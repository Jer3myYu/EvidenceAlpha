## 5. Python code quality

Baseline: the **Google Python Style Guide** (<https://google.github.io/styleguide/pyguide.html>). It applies to every `.py` file in this repo. The rules below are the ones that get checked; the guide settles anything it does not cover.

- **Formatting** — 4-space indent, never tabs. Max line length **80**. Formatting is a tool's job, not a review topic: `black` with `line-length = 80`, configured in `pyproject.toml`.
- **Naming** — `modules_like_this.py`, `ClassesLikeThis`, `functions_and_vars_like_this`, `CONSTANTS_LIKE_THIS`, `_internal` with one leading underscore. No dashes in filenames.
- **Imports** — import *modules*, not the symbols inside them: `from retrieval import retriever`, then `retriever.search(...)`. Never relative (`from .x import y`); always the full path from the repo root. One import per line, grouped stdlib → third-party → local, alphabetized within each group. `typing` / `collections.abc` symbols are the standard exception.
- **Docstrings** — Google style (`"""Summary line."""` ≤ 80 chars, then `Args:` / `Returns:` / `Raises:` where they apply) on every public module, class, and function. Trivial private helpers may go without.
- **License boilerplate** — agreed deviation from the Google guide (2026-08-16): files carry no license header; the module docstring opens the file.
- **Types** — annotate every public API. Prefer `X | None` over `Optional[X]`.
- **Errors** — no bare `except:`; catch the specific exception; keep the `try` body to the line that can actually fail. Never use `assert` for runtime validation — it is stripped under `-O`. Fail loudly rather than returning a silent empty result, especially in retrieval and ingestion.
- **Defaults** — no mutable default arguments; use `arg=None` and build the value inside.
- **Lint** — `pylint` with Google's `pylintrc`. Work is not done while the linter is unhappy.
- **Tests** — `pytest`. **[SUPERSEDED 2026-09-02]** ~~Unit tests mirror the source layout under `tests/unit/`; anything that touches the network, ChromaDB, or SQLite belongs in `tests/integration/`.~~ Phase 1 keeps a single, readable `tests/test_rag.py`; split only when a later phase needs it.

## 7. Python environment

- This project runs in a **virtual environment at `.venv/` in the repo root**. Nothing is ever installed into the system interpreter.
- Interpreter: `pyproject.toml` requires **Python 3.11+**, and the default `python3` on this machine is 3.10.12. Build the environment on the installed 3.12 instead: `python3.12 -m venv .venv`. Install `torch` from the CPU wheel index before `pip install -e ".[dev]"` (the command is in `pyproject.toml`); the environment was rebuilt this way on 2026-09-02 and again on 2026-09-03 for Phase 9 (crewai forces chromadb 1.1.x, pydantic 2.12, mcp 1.28; prove a pin change in a disposable venv first).
- Activate before any Python or `pip` command: `source .venv/bin/activate`. In a non-interactive shell, call the binaries directly — `.venv/bin/python`, `.venv/bin/pip` — rather than relying on an activation that did not persist.
- Dependencies are **declared in `pyproject.toml`**, then installed. A one-off `pip install` that is not written down does not count as a dependency.
- Adding a new third-party dependency is a decision, not a detail: propose it before installing.
- `.venv/` is gitignored and disposable. It must always be reproducible from `pyproject.toml` alone — never commit it, never hand-patch it.
